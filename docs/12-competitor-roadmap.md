# Shadowalker：同行独立站拆解与功能优化清单

调研日期：2026-09-23。对象：高尔夫车、电动船、电动自行车、自行车电动改装。

**1.3.0 实施进展（2026-09-23）：**本轮完成下述六项的技术基础：F01 结构化资料、F02 详情模块、F09 同类对比、F10 五维兼容初筛、F11 询价配置及保存/分享、F13 选购方案进入聊天。F01/F02 仍需真实产品与素材；F10 尚无完整车型/安装数据库；F11 尚未绑定可购买变体、价格和正式报价；F13 尚未接入真实知识库机器人。其余条目保留为后续路线图，不能视为全部完成。升级和验收见 [选购工具文档](11-selection-tools.md)。

## 结论与建议

Shadowalker 的下一步重点应是让用户能够选对产品、判断是否适配、知道如何交付，并把选购结果交给客服继续沟通。现有科技风、品牌价值主张和直接聊天已经构成基础；优先完善产品决策和报价流程。

建议保留品牌宣言在首页首屏，在具体商品页把空间留给真实产品、关键规格、交付信息和下一步操作。为四类产品设计不同路径：

| 产品 | 建议购买路径 | 主要疑问 |
|---|---|---|
| 高尔夫车 | 使用场景 → 座位/电池/附件配置 → 目的地 → 带配置聊天 → 正式报价 | 能坐几人、适用场地、交期、运输和售后 |
| 电动船 | 使用水域/人数 → 型号 → 有条件的续航说明 → 试航或视频看船 → 报价 | 航程是否满足、充电、实际体验、当地交付与维护 |
| 电动自行车 | 用途/身高 → 筛选与对比 → 车型/尺码 → 配送确认 → 购买 | 尺码是否合适、骑乘用途、可配送区域 |
| 改装配件 | 现有自行车 → 兼容性检查 → 套件/缺少部件 → 安装支持 → 购买 | 装不装得上、还缺什么、是否需要专业安装 |

这是一份基于公开页面和现有项目代码的功能研究。“优秀”指特定流程值得借鉴，不代表对这些公司的经营状况或产品质量背书。没有提交预约、联系方式、订单或付款，也没有竞品后台转化率数据。文中“作用/收益”为产品设计判断，需要 Shadowalker 自身数据验证。

## 一、8 个参考站：看到了什么，怎么借鉴

### 1. Club Car：先确定用途，再进入配置和经销商咨询

**已观察到：**车辆构建入口区分商业与高尔夫用途，提供配置后连接经销商的路径，以及输入 Build Code 恢复已保存车辆的入口。官网另列有手册、选车帮助和试驾经销商入口。[配置页面](https://www.clubcar.com/en/build)

**判断与建议：**Shadowalker 的高尔夫车分类可先问个人、酒店园区或车队用途，再提供座位等配置。保存一个配置编号，让后续聊天、报价使用同一份记录。不要让个人买家和批量采购客户阅读同一套泛化文案。对应 F11、F21。

### 2. Garia：把高客单价配置变成可讨论、可带走的方案

**已观察到：**配置页包含型号/选项、配置 ID、联系销售和邮件发送 PDF 的入口；同时说明展示价格未包含的运费、税费等项目。动态价格计算本次未完整操作验证。[配置页面](https://www.garia.com/configurator/)

**判断与建议：**Shadowalker 可以提供配置摘要与报价依据，并区分产品价、运输和待确认项目。用户应先看到方案，下载或继续聊天无需被迫留邮箱；邮件发送作为可选功能。对应 F03、F11、F18。

### 3. Candela：用有条件的技术解释回答电动船的购买顾虑

**已观察到：**C-8 产品页结合场景与技术内容，提供人数、速度等输入的续航计算入口，并说明实际结果可能变化；另有试航预约页面。[C-8 产品页](https://candela.com/leisure-boats/candela-c-8/)、[试航预约](https://candela.com/test-drive-c-8/)

**判断与建议：**Shadowalker 电动船先发布实际测试工况和航程表，再考虑计算器。没有经过验证的能耗数据时，不应制造精确航程结果。高客单价产品还可以提供真实可预约的视频看船或试航。对应 F02、F19、F20。

### 4. X Shore：配置、交付信息和销售对接处于同一条路径

**已观察到：**配置页可见船型版本、套餐比较、颜色/附加项、配置分享链接、交付信息、询价和试航入口；套餐包含关系也在页面提示。[X Shore 1 配置页](https://xshore.com/configurator/x-shore-1/)

**判断与建议：**Shadowalker 的配置应记录“已包含”和“另购”项目，避免重复购买。分享出去的配置可直接传入聊天，客服不必再次问型号、电池和选配。对应 F11、F13、F17。

### 5. Aventon：通过可选择的参数对比减少来回翻页

**已观察到：**比较页允许选择车型与要比较的功能，包括续航、电机、重量、用途、电池、刹车、载重等；列表页还呈现评价和保障信息。[参数比较](https://www.aventon.com/pages/compare-aventon-ebikes)、[车型比较入口](https://www.aventon.com/collections/compare-tool)

**判断与建议：**Shadowalker 首版允许同类 2–3 款产品比较，默认突出 6–8 个关键差异。比较字段须统一单位和测试口径，不能直接拿营销文案拼表。对应 F01、F09。

### 6. Cowboy：将选车、体验和服务支持接起来

**已观察到：**首页展示选车问答入口、试骑入口、服务支持说明，以及保养、保修等服务链接；产品技术内容与骑行场景交替呈现。保养子页面本次未能成功读取，服务细节不作推断。[官网首页](https://cowboy.com/)

**判断与建议：**Shadowalker 可用少量问题询问用途、身高和道路条件，解释推荐理由；没有真实试驾或服务网点时，先提供视频咨询及清楚的支持范围。对应 F05、F12、F20。

### 7. Swytch：把“我的车能不能装”变成独立的转化入口

**已观察到：**适配页面收集自行车品牌、型号和是否改动前叉/车把，提供照片上传与报告发送入口；页面还可见地区/币种选择和帮助中心。[适配检查页面](https://www.swytchbike.com/will-it-fit-my-bike/)

**判断与建议：**这是 Shadowalker 改装业务最值得优先借鉴的功能。采用已验证适配、明确不适配、需要人工确认三种结果；未知型号转入聊天。保留直接沟通的原则，适配初筛不强制留邮箱。对应 F04、F10、F15。

### 8. Grin Technologies / ebikes.ca：让专业工具和教程建立技术可信度

**已观察到：**电机模拟器允许结合电机、电池、控制器、轮径、车辆与总重等条件分析表现；同页提供图表解释和教程，包含方案对比的教学内容。[模拟器及使用说明](https://ebikes.ca/resources/web-tools/simulator.html)

**判断与建议：**Shadowalker 的“科技极客”气质可以体现在接线图、部件说明、兼容规则和真实测量依据上。先做准确的知识库和简明工具，再考虑需要工程模型的模拟器。对应 F10、F15、F19。

## 四、第一轮具体做什么

建议按依赖推进，不同时摊开全部 24 项：

1. **准备基础资料：F01 + F02 + F03。** 先完成每类代表性商品，再扩展全部 SKU。没有准确数据，比较、配置和机器人会一起失真。
2. **补齐运营与上线条件：F04–F08。** 技术工作可以先做，真实支付、配送和客服时效需要经营资料才能完成。
3. **先把改装业务做深：F10 + F15，再接 F13。** 兼容性问题直接影响客户是否敢买，也能体现 Shadowalker 的技术气质。
4. **为整车建立方案：F11 + F18，再接 F13。** 先做二维照片与选项摘要，不等待 3D 资源；把方案保存为可报价的记录。
5. **增加跨型号选购效率：F09 + F12。** 根据 SKU 数量和用户问题决定何时上线；同类只有一款产品时，比较工具暂时没有价值。
6. **资料完善后启用 F14，持续做 F16。** 机器人先服务常见产品问题，复杂兼容性和商业承诺由人工确认。

当前最值得排进下一开发批次的六项是：**结构化参数、商品详情升级、改装兼容检查、轻量配置器、同类产品对比、聊天携带选购上下文**。其中前两项是后四项的基础。

## 五、结合现有 WordPress 项目的实现方式

这是针对现有项目的实现建议，不是对竞品技术栈的推断。

- 商品主数据继续由 WooCommerce 管理；可筛选字段使用统一属性或类型化元数据。先解决 `_sw_specs` 自由文本无法可靠比较/计算的问题。
- 配置器引用真实变体和选项规则，保存不可歧义的配置版本。库存/价格确定、适合直接购买的产品才进入购物车；需核实运输或商业条件的整车继续走询价。
- 兼容规则与技术文档放在可独立维护的数据层，主题只负责展示。需要照片时增加私有上传与客服访问控制，不直接复用公开媒体链接存客户照片。
- 复用现有聊天模块增加上下文与处理状态，不重新建立一套聊天系统。聊天 API 已有私有会话和机器人协议，可以逐步扩展。
- 语言、国家和币种继续各自建模。参数的数值是同一份，字段标签和解释按语言翻译；型号、SKU 和单位转换保持一致。
- SEO 内容覆盖实际产品问题；配置结果、客服会话、内部报价不作为批量可索引的搜索页面。避免把几十种筛选组合自动做成内容重复的落地页。
- 不在这一阶段堆叠多个重叠功能的插件。先明确数据与验收条件，再选择扩展或自定义实现。

## 六、内容选题样例

下列是待做搜索量与难度验证的选题方向，并非已经证明有流量的关键词：

| 品类 | 选题 | 页面内应引导的动作 |
|---|---|---|
| 高尔夫车 | 酒店/园区如何按人数与路况选择车型；座位和电池配置怎么选 | 进入用途筛选和配置 |
| 电动船 | 不同载荷与航速怎样影响航程；码头充电要确认哪些条件 | 查看对应型号工况资料、预约咨询 |
| 电动自行车 | 通勤与休闲骑行选车差异；不同身高如何选车架 | 车型对比和尺码选择 |
| 改装配件 | 如何测量安装尺寸；控制器/电池/电机兼容性检查；安装前需要哪些部件 | 适配检查和支持中心 |

国家相关法规、认证或支付细节需按具体市场另外核实，不把其他品牌的适用结论直接用于 Shadowalker 产品。

## 七、如何衡量效果

先采集基线，再判断改动是否有价值，不预设“转化提升百分之多少”。

| 功能 | 建议观察指标 | 防止误判 |
|---|---|---|
| 商品页 | 有效访问到咨询/购买操作的比例 | 按品类、国家与设备区分，整车询价不与配件购买混算 |
| 适配检查 | 完成率、需人工确认比例、适配错误相关售后 | 完成率高但错误结果多并不成功 |
| 配置器 | 开始到保存、保存到有效报价的比例 | 排除无意义重复点击；识别真实销售跟进 |
| 聊天/机器人 | 首次人工响应时间、解决率、转人工与重复咨询 | 不把自动欢迎语或机器即时响应当成人工解决 |
| 内容 SEO | 非品牌搜索入口、关联产品访问、有效咨询 | 不只追求文章数量和曝光 |
| 国际化成交 | 国家/币种维度支付成功与退款一致性 | 与实际商户、配送和产品可售条件一起分析 |

## 八、暂缓事项

- 全屏粒子、持续动画和先行制作大量 3D 效果：当前优先保证商品信息和手机操作效率。
- 对所有整车直接开放全额在线支付：先具备可确认的交付、税运和退款流程。
- 没有实测依据的精准续航计算器、没有服务能力的试驾网点图。
- 用生成内容冒充真实用户评价、工程测试或产品认证。
- 让机器人自行作出不在已审核资料内的价格、库存、续航或合规承诺。

本报告为调研与规划交付，未据此改动商城功能或购买任何第三方服务。
