# 测试、上线和持续运维

## 自动检查

GitHub Actions 执行 PHP 语法检查、翻译完整性、Docker WordPress/MariaDB 启动、插件安装、演示数据两次导入、PHP 业务断言与 HTTP 冒烟测试。CI 不持有真实密钥，依赖 WordPress.org/Docker Hub 可用；付费 WPML 与网关真实账户不在自动安装范围。

本地：

```sh
python scripts/build-translations.py
python tests/check-translations.py
docker compose --profile tools run --rm cli wp eval-file /workspace/tests/integration.php
python tests/http-smoke.py http://localhost:8080
```

集成测试在临时产品上验证询价商品及变体不可购、正常配件可购、无虚假 Offer、输入校验、私有询价权限、翻译实际加载。测试创建的商品会清理。只在本地/预发布执行；HTTP 测试会提交测试询价，应通过后台删除。

## 上线验收清单

| 范围 | 必须确认 |
|---|---|
| 品牌和内容 | Logo、公司资料正确；无演示产品/价格/规格/政策；没有虚构认证或评价 |
| 导航 | 首页、四分类、产品、故事、联系、政策、搜索、404、页脚链接正常 |
| 设备 | 360/390/768/1440px，无横向溢出；菜单、焦点、表单错误可理解 |
| 目录 | 库存、变体、图片、规格与真实资料一致；技术信息经产品负责人审查 |
| 询价 | 正常/无效/重复/nonce 过期/蜜罐；后台可查；邮件失败不丢单；权限隔离 |
| 购物车 | 添加、删除、数量、优惠券、库存不足、直接请求询价商品、变体和 Store API |
| 结账 | 地址、国家、运费、税、币种、最小单位、条款、访客/注册客户购买 |
| 支付 | 成功、失败、3DS、取消、重复回调、异步到账、全/部分退款、Webhook 日志 |
| 多语言 | 五语言核心页面/商品/分类/邮件；库存共享；语言/币种切换金额一致 |
| 搜索 | 分类、SKU、商品名称搜索有效；空结果页可返回商城 |
| SEO | 标题/描述/唯一 canonical、正确 hreflang、sitemap、真实 Product schema、无测试页收录 |
| 安全 | HTTPS、后台强密码/MFA、最小权限、备份加密、未泄露 .env 与日志 |
| 性能 | 实际手机网络、页面缓存排除、语言/货币缓存正确；没有 JS/PHP 致命错误 |
| 运维 | Cron/Action Scheduler、邮件、证书、支付/失败订单监控、恢复演练 |

完成后先在真实支付模式进行受控小额付款退款，确认平台和订单一致；再逐步开放流量。切换正式内容后关闭演示横幅：

```sh
docker compose --profile tools run --rm cli wp option update sw_demo_mode 0
docker compose --profile tools run --rm cli wp option update blog_public 1
```

第二条只适用于准备公开索引的正式站；预发布永远不执行。WooCommerce 站点可见性另行在后台设定。

## 运维频率

- 每天：检查失败支付、待处理异步订单、询价通知失败、邮件退信、备份、磁盘与异常日志。
- 每周：在预发布测试安全更新、核查计划任务/库存、抽查下单与询价路径。
- 每月：演练一次恢复、复核管理员权限、核对退款和结算、检查 SEO 覆盖及跨语言内容。
- 发生安全修复：按影响尽快预发布验证并发布，记录版本；不要长期冻结旧插件。

建议数据库每日全量 + 适合订单量的增量备份，文件每日或变更时备份，异地保留 7 日每日、4 周每周、若干月月度（根据业务和隐私要求决定）。RPO/RTO 需要运营批准；备份成功不等于恢复成功。

## 安全与隐私维护

询价数据保存于 WordPress 私有内容，并包含姓名和邮件。数据保留时限需要业务确定后执行清理，不默认永久合理保存。WordPress 工具支持按邮箱导出/删除询价；订单税务留存要求另行评估，不能把询价删除功能当作所有系统的数据删除。

为管理员启用 MFA；店铺运营使用 shop_manager，内容人员使用最小权限角色。禁止多个人共用一个管理员账号。限制登录尝试、审计后台变更；不要安装来源不明的破解商业插件。公共站部署 WAF 时，要确保没有误拦网关 Webhook 和结账请求。

缓存排除：购物车、结账、账户、`/wp-admin/`、`/wp-json/wc/store/`、`wc-ajax`、支付回调、询价 POST。带有会话/购物车 cookie 的请求绕过整页缓存。询价页面的 nonce 有时效；避免超长期页面缓存导致用户无法提交。

## 故障处理

支付异常先暂停受影响方式，核对网关交易，避免重复扣款；邮件异常保留后台处理并恢复邮件通道；商品配置错误立即下架受影响商品；数据库恢复先隔离新写入，并记录事故窗口的新订单处理方案。

代码、数据库和上传目录应配套备份。客服工单或 issue 中只放已脱敏日志。生产监控告警渠道由店铺配置，本次开发不会自动给客户或第三方发送消息。
