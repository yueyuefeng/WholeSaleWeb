# 选购工具、结构化商品与聊天方案（1.3.0）

1.3.1 体验更新：商品下拉列表支持当前列表内搜索；对比表可只显示差异并直接咨询，来源/版本始终保留；配置冲突即时提示；未保存草稿在当前标签页保留最多 24 小时；保存后修改输入会隐藏旧方案，提交期间锁定表单避免选择与结果不一致；结果提供复制链接及剪贴板不可用时的手动复制。旧版本方案仍可读取。

草稿保存在浏览器 sessionStorage，按语言、商品和工具隔离，资料修订变化或草稿超过 24 小时后不恢复。“清空草稿”只清当前表单草稿，不删除已保存的分享方案。禁用浏览器存储时仍可填写和保存，但无法恢复草稿。

本轮交付竞品研究建议的六项选购能力：结构化参数、商品详情、同类对比、改装兼容初筛、整车询价配置、选购上下文进入聊天。这是可运行的技术版本；真实商品、可生产组合、交付、价格和兼容规则仍需品牌方审核录入。研究清单中的 24 项并未全部完成。

## 用户操作

| 入口 | 行为 |
|---|---|
| 商品详情 | 关键参数、亮点、场景、限制、包装清单、交付、质保、测试条件；缺失内容显示待确认。原有自由文本规格保留为补充 |
| 商品列表/详情的“商品对比” | 选择同品类的 2–3 款；表格突出差异、统一单位、展示来源/版本，手机在表格内横向滚动 |
| 高尔夫车/电动船的“定制出行方案” | 选择配置、目的国和数量；强制校验依赖与互斥，生成包含项目摘要 |
| 改装产品的“检查兼容性” | 可选自行车品牌/型号；填写轮径、开档、电压、电机位置和制动类型，未知留空；提供开档测量示意 |
| 保存方案 | 随机链接分享，有效 30 天；下载 UTF-8 纯文本摘要；带方案进入聊天 |
| 联系页 | 发送前显示方案摘要；客服后台和机器人接口收到同一份服务端方案，无须先留姓名/邮箱 |

兼容结果为“初步匹配、规格不匹配、需人工确认”。只有资料已审核、五项规则齐全且所有输入符合，才给出初步匹配。这不是安装批准：车架/前叉强度、接头、刹车断电、扭矩臂、安装空间仍需专业检查。品牌/型号仅供客服判断，本版没有厂商车型数据库。

## 升级与部署

1. 备份数据库、上传文件、主题与插件，在预发布环境同时安装 1.3.0 主题与 Core。
2. 新装演示站继续运行 `wp shadowalker seed`；已有演示站可运行 `wp shadowalker selection-demo`，只添加缺失工具页，并为 `_sw_demo=yes` 且尚无 `_sw_profile` 的既有演示产品补资料，不覆盖已有数据。
3. 正式站无需导入演示商品。在后台“页面”创建下表页面并发布，可加入菜单；商品自动提供相应入口。

| 页面别名 | 页面内容 |
|---|---|
| `compare` | `[shadowalker_compare]` |
| `build` | `[shadowalker_build]` |
| `compatibility` | `[shadowalker_fit]` |

4. 保存固定链接、清除静态资源缓存，检查商品页与三个工具页。
5. CDN/整页缓存排除以上页面、各语言译版、带 `plan` 的页面、`/wp-json/shadowalker/v1/selection/` 和等效 `rest_route` 请求；保持联系页和聊天接口的原有排除。带创建 nonce 的商品页缓存须短于 nonce 有效窗口，或直接排除。
6. 沿用生产系统 cron，每日执行过期清理。演示状态和禁止索引保持到数据、交易与政策完成验收。

Docker 命令示例：

```sh
docker compose --profile tools run --rm cli wp shadowalker selection-demo
```

使用既有 WordPress 商品元数据与自定义文章，无自建 SQL 迁移。回退需同时恢复旧主题/Core；新方案元数据可保留，旧版本不读取。需要恢复完整数据时使用升级前备份。

## 后台商品资料

位置：“商品 → 编辑 → 商品数据 → 常规 → 选购参数与规则”。先选品类，填资料来源（文档名/编号/URL）、版本和参数，再填亮点、场景、限制、包含清单、交付、质保与测试条件。未知值留空，不用 0 代表未知。

核对来源、规格、选项和兼容规则后才勾选“产品资料已审核”。审核必须有来源及版本；有实测续航还必须有测试条件。演示商品始终视为未审核。验证失败时给出后台错误并整体保留旧选购资料；WooCommerce 普通字段仍按正常流程保存。

| 存储字段 | 内容 |
|---|---|
| `_sw_profile` | `kind`、`verified`、`source`、`version`、`values`、`content` |
| `_sw_options` | 选项分组、依赖、互斥、已包含项目 |
| `_sw_fit` | 各兼容维度的允许值列表 |
| `_sw_demo` | `yes` 强制未审核，仅演示使用 |

品类 `kind` 为 `cart / boat / bike / kit`，缺失时从现有四个商品分类推断。统一参数如下：

| key | 单位 | 适用品类 |
|---|---|---|
| seats | 个，整数 | 车 / 船 |
| power_w | W，额定功率 | 全部 |
| battery_wh | Wh | 车 / 船 / 自行车 |
| voltage_v | V | 全部 |
| weight_kg | kg | 全部 |
| payload_kg | kg | 车 / 船 / 自行车 |
| range_km | km | 车 / 自行车 |
| range_nm | NM（海里） | 船 |
| length_m / draft_m | m | 船 |
| wheel_in | in | 自行车 / 改装 |
| axle_mm | mm | 改装 |
| rider_min_cm / rider_max_cm | cm | 自行车 |

数字范围只用于防止明显录入错误，不能证明实际性能。没有英制/公制切换器。`content` 包含 `highlights / use / limits / included / delivery / warranty / conditions`，每段最多 1500 字符；来源最多 240、版本最多 60 字符。续航应注明速度、载荷、温度、水况/路况等实际测试条件。

## 配置规则 JSON

以下仅为格式示例，不能直接作为实际生产规则：

```json
[
  {"id":"seats","label":"座位","options":[
    {"id":"four","label":"4 座"},
    {"id":"six","label":"6 座","requires":{"battery":"extended"}}
  ]},
  {"id":"battery","label":"电池方案","options":[
    {"id":"standard","label":"标准方案"},
    {"id":"extended","label":"扩展方案","includes":["扩展电池组件"]}
  ]}
]
```

- 最多 6 组，每组 1–10 个选项；ID 为小写字母开头、后续字母/数字/下划线/短横线，最多 30 字符，在各自范围唯一。
- `requires: {"group_id":"option_id"}` 必须同时选中，`excludes` 不得同时选中；服务端检查引用存在及每次提交组合。运营还需确认整套规则至少存在一组可满足的组合。
- `includes` 每项最多 100 字符、最多 10 项，摘要去除完全相同的重复项。
- `label` 是展示文案。配置摘要表示客户偏好，不改写基础型号详情参数。
- 当前是**询价偏好配置器**，没有映射 WooCommerce 可购买变体，不计算价格、不锁库存、不生成订单，不保证所有组合可生产。无 PDF、邮件发送或正式报价功能；这些留待真实 SKU、商务和物流规则接入。

## 兼容规则 JSON

以下为测试格式，须替换成厂商审核的实际数据：

```json
{
  "wheel_in":[26,27.5], "axle_mm":[135], "voltage_v":[36],
  "mount":["rear"], "brake":["disc"]
}
```

数字按统一单位精确匹配，不隐式推算公差；`mount` 为 `front / rear / mid`，`brake` 为 `disc / rim`；各项最多 20 个允许值。非法键、对象或数值被拒绝。无规则、无测量、未经审核均交人工。700C、ETRTO 标识不能直接当作英寸数字；不确定留空。中置安装尺寸、不同接头、电池安装空间不能由五项通用规则证明，保留未知项并人工确认。

电池和控制器同属改装品类，但本工具不能替代其专用匹配规则。不要给独立配件填写虚假的轮径或开档以获得“匹配”。

## API、分享与版本

`POST /wp-json/shadowalker/v1/selection/plan` 示例：

```json
{"mode":"build","product_id":123,"choices":{"seats":"six","battery":"extended"},"country":"DE","quantity":2}
```

兼容用 `mode: "fit"`、`measurements` 对象、可选 `bicycle: {"brand":"…","model":"…"}`。品牌/型号各最多 100 字符，不提供联系方式字段。目的国可空，非空为 WooCommerce 国家代码；数量为 1–10000 整数。

创建需 `X-Shadowalker-Nonce`，登录时同时带 `X-WP-Nonce`。Origin 校验复用聊天；每个直连 IP 每小时最多 30 次。成功返回 201 与 `plan / summary / url / chat_url`；无效输入 422、商品不存在 404、CSRF/Origin 403、限流 429。客户端传来的认证、价格、判定结果不作为依据。

`sw_plan` 是非公开文章，无公开 REST 列表。分享码为 128 位随机值，数据库仅存 SHA-256；显示编号 `SW-…` 不能单独恢复方案。**持有分享链接即可查看方案**，所以不要在品牌/型号里填写个人或保密资料。方案不包括聊天记录或聊天密钥。

快照含产品ID/名称/SKU、生成时间、资料版本和修订摘要、选项或测量、判定。产品名称、资料、规则变化后标记过时，原初步匹配降为人工确认；产品下架、加密码、删除或链接过期不可读取。

工具页/方案页使用禁止缓存头和 `X-Robots-Tag: noindex, follow`，并设置 WordPress robots；短代码识别适用于翻译页。不要把方案链接放进 sitemap，也不要通过 robots.txt 禁抓取后期待搜索引擎读到 noindex。CDN 必须另配排除，否则可能绕过 PHP 响应头。

`sw_chat_cleanup` 每日删除过期方案，每批最多 100 条、积压继续安排；生产调度决定实际删除时间。备份保留期另行管理。

## 聊天与机器人

创建聊天传 `plan`，服务端验证后保存 `_sw_selection`，产品以方案为准，不信任客户端伪造对象。不同方案使用独立聊天存储键，避免混用。

`sw_chat_bot_context()` 新增 `selection`：无方案为 `null`，有方案为快照和重新计算的 `stale` 状态。每次机器人调用及后台展示都检查修订变化，不传方案分享码和聊天 token。供应商应将 `verified=false`、`stale=true`、未知和不匹配结果交由人工，不把客户输入当产品事实。

删除聊天会删除其快照副本，但不撤销方案分享；方案到期不自动删除仍在保留期内的聊天副本。正式隐私政策需说明。真实模型没有接通，接入方式仍见 [聊天与机器人](10-chat-and-bot.md)。

## 多语言、资源与限制

- UI 支持英文和简中/德/法/西；1.3.0 四套目录各 242 条，当前源码 225 条。自动生成的默认工具页标题随语言变化，自定义标题由运营维护。
- WPML 配置中 `_sw_profile / _sw_options` 为 `copy-once`，各语言商品编辑器需翻译说明/选项并独立审核；`_sw_fit / _sw_demo` 复制。来源变更不会自动同步 copy-once 字段，发布时须逐语言核对数值和版本。三工具页建立 WPML 译版并保留短代码。WPML/WCML 商业插件尚未实际联调。
- 选择器默认查询最多 200 个目录可见商品再筛品类；1.3.1 会额外纳入通过链接选定的有效商品，防止超过目录上限后无法配置。默认列表排除隐藏商品，精确商品链接仍遵循 WooCommerce 公开商品行为。列表内搜索仅过滤已加载选项，大目录全站检索仍须升级为分页/搜索接口。
- 沿用现有 WordPress、PHP、数据库及静态资源，无需新增付费配置器或消息服务器；数据库容量随方案数量和保留期增长。
- 上线资源仍包括审核规格表、SKU、可生产配置、兼容规则、自有实拍/安装资料、交付/保修政策、销售市场、客服与商户账户。
